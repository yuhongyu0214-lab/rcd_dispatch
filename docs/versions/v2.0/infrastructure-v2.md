## 1. 白话结论

中国大陆正式生产主线使用阿里云。当前应用继续保持一个 Next.js 模块化单体，不拆微服务：同一份代码构建为同一个不可变镜像，在 ECS 上分别运行 Web/API app 和后台 worker；数据库迁移由一次性 migration 任务执行。Nginx 负责公网入口与 HTTPS，RDS PostgreSQL 保存业务事实，Redis/Tair 保存实时和短期数据，ACR 保存生产镜像，集中日志平台保存可查询、可告警的结构化日志。

Railway 仅保留为历史 Demo 证据；CloudBase 只能承载假数据或脱敏后的独立测试数据。两者都不是中国大陆正式生产主线。

## 3. 目标架构与当前事实

### 3.1 正式目标架构

```text
用户 / 司机 H5 / 调度员 Web / 获准订单来源
                         |
                  域名 + HTTPS
                         |
                      Nginx
                         |
                 Next.js app/API
                    /         \
          RDS PostgreSQL     Redis/Tair
             业务事实       实时位置/缓存/短锁
                    \         /
              一次性 migration
                       |
              后台 worker（单副本）
                       |
                DispatchEventOutbox

构建产物：Git commit SHA → 同一不可变镜像 → ACR
运行日志：app / worker / Nginx / 系统 → 集中日志平台（阿里云默认 SLS）
地图与 ETA：app 服务端调用高德；浏览器只使用地图渲染所需公开配置
```

## 4. 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| ECS | 承载 Docker、Nginx、app、worker 和受控的一次性 migration 运行环境 | 不直接保存业务事实 |
| Docker 镜像 | 固化同一提交的应用代码和运行依赖 | 不保存环境秘密，不绑定单一运行角色 |
| Nginx | HTTPS 终止、域名入口、请求转发、基础请求保护 | 不实现业务鉴权和业务状态机 |
| Next.js app/API | Web、内部 API、业务编排和外部服务适配 | 不直接承担周期任务调度 |
| worker | 周期调用 app 的受保护内部处理端点，由 app 事务处理待处理 outbox | 不直接连接 RDS/Tair，不执行数据库迁移，不暴露公网业务入口 |
| migration | 一次性执行获准的数据库迁移并退出 | 不是常驻服务，不与 app/worker 并发抢迁移 |
| RDS PostgreSQL | 唯一业务事实库：订单、调度、执行、预警、审计和 outbox | 不存短期缓存语义 |
| Redis/Tair | 最新位置、在线状态、ETA 短缓存、短锁等实时/短期数据 | 不是业务事实来源 |
| ACR | 保存与 Git commit SHA 对应的不可变生产镜像 | 不接收 `latest` 作为唯一生产追溯依据 |
| 集中日志平台 | 收集、查询、留存和告警结构化运行日志 | 不代替业务操作审计表 |
| 高德 | 地理编码、路径、地图、真实 ETA 和导航输入 | 不决定司机、槽位、锁定或业务状态 |
| OSS | 仅在已批准的文件业务出现时保存对象文件 | 当前不是默认必需组件，不扩展 PRD |

## 5. app、worker、migration 边界

三种运行角色使用同一个 commit SHA 对应的同一镜像，但启动命令、权限和生命周期不同：

| 角色 | 生命周期 | 网络入口 | 数据库权限原则 |
|---|---|---|---|
| app | 常驻 | 仅由 Nginx 转发获准公网请求 | 业务运行所需最小权限 |
| worker | 常驻，第一版单副本 | 无公共入口；只调用内部受保护能力 | 第一版不注入数据库凭据，数据访问由 app 完成 |
| migration | 每次发布最多一次，成功或失败后退出 | 无公共入口 | 仅迁移窗口临时授予的必要 DDL 权限 |

约束：

- app 与 worker 不得自行在启动时并发执行 migration。
- HTTP-only worker 不得注入 `DATABASE_URL`、`REDIS_URL`、owner 凭据或高德服务端 Key。
- migration 成功前不得启动依赖新结构的新版本 app/worker。
- worker 多副本不是当前默认能力；启用前必须重新验收租约、幂等、积压和告警。
- worker 第一版按每分钟周期处理待处理事件；十分钟基线事件按稳定时间桶幂等生成。周期值变更必须与 Gate 3 事件契约和验收同步复核。
- app、worker、migration 不共享长期超级管理员权限。

## 6. 数据与依赖边界

### 6.1 业务事实

RDS PostgreSQL 是唯一业务事实库。订单、Assignment、计划版本、执行状态、预警、操作审计和 outbox 均以数据库提交结果为准。

Redis/Tair 故障时允许实时能力降级，但不得产生第二套业务事实，不得用缓存覆盖数据库事实。降级的具体运行和告警方式由运维指南定义。

### 6.2 高德

高德只提供真实地理和 ETA 输入。高德失败、超时、配额不足或无路径时，系统必须明确标记 ETA 不可用，不得填入演示数字，也不得由基础设施层代替调度核心做业务决定。

### 6.3 外部订单源

外部订单源经 Adapter 和内部 API 进入系统。基础设施只提供安全、可用的传输边界，不得让外部平台直接修改内部调度事实。

阿里云、Railway、CloudBase 或其他平台的配置和 SDK 不得进入调度核心。平台差异只能停留在部署定义、基础设施适配或外部 Adapter 边界。

## 7. 网络与安全边界

- ECS、RDS、Tair 使用正式 RDS 的同一地域、同一 VPC；具体地域名称只读核验后登记，不得猜测。
- RDS 与 Tair 仅允许来自获准应用网络的最小访问范围，不开放全网白名单。
- 公网只暴露 Nginx 必需端口；RDS、Tair、worker 和 migration 不直接暴露公网。
- ECS 管理入口使用最小来源范围、最小账号权限和可审计方式。
- 面向中国大陆公网提供正式服务前，域名、主体和接入资源必须完成适用的 ICP 备案/许可核验；未完成时只能用于获准的内部或隔离验证，不得冒充正式生产入口。
- 生产秘密由获准的秘密管理或受控环境注入，不写入 Git、镜像、日志、截图和文档。
- app、worker、migration 使用相互独立且最小化的权限边界；共享密钥必须有明确用途和轮换规则。
- 匿名存活检查与受保护的依赖就绪检查沿用 API 契约定义，基础设施不得扩大匿名信息暴露。

## 8. 环境隔离

| 环境 | 数据要求 | 外部资源要求 | 允许用途 |
|---|---|---|---|
| 开发 | 本地或专用开发数据 | 不得连接正式生产数据 | 日常开发 |
| 测试 | 合成数据或脱敏数据 | 独立数据库/缓存或明确隔离命名空间 | 自动化与集成测试 |
| 预生产 | 脱敏、规模受控 | 与生产相似但权限和数据隔离 | 发布演练 |
| 生产 | 真实业务数据 | 阿里云正式资源，最小权限 | 对外正式运行 |
| CloudBase 临时预览 | 仅假数据或脱敏独立数据 | 无生产秘密、无生产数据权限 | 临时 UI/演示验证 |
| Railway 历史 Demo | 不再作为生产基线 | 只保留历史证据 | 审计追溯 |

环境之间不得共用生产数据库账号、Redis 凭据、司机位置数据或管理员默认密码。

## 9. 可用性阶段

### 9.1 第一版：成本优先试运行（已批准）

允许单 ECS 承载 Nginx、app 和单副本 worker，但必须明确：

- ECS 是单点；
- 维护窗口会造成服务中断；
- 不承诺实例故障自动切换；
- 仍必须有 RDS 备份、镜像回退、集中日志和恢复演练。

### 9.2 后续：稳定生产

多实例、负载均衡和 worker 多副本属于后续可用性升级。启用前需重新评估会话、定时任务唯一性、数据库连接、缓存锁、共享存储和发布编排，不得只复制容器数量。

第一版已选择单 ECS 试运行。该裁决不授权采购或部署；具体规格仍需资源盘点和实施审批。

## 10. 明确不建设

当前 V2 不建设：

- 微服务拆分；
- Kubernetes；
- 分布式数据库；
- 第二套后端；
- 多租户、计费和复杂组织权限；
- 未有文件业务时的 OSS；
- 由基础设施层实现的调度规则；
- 以 Railway 与阿里云双主线并存的生产架构。

## 11. R7 冻结决策摘要

| 决策 | 冻结结果 |
|---|---|

## 12. 初稿验收

- 阿里云是唯一正式生产主线。
- Railway 只作为历史 Demo。
- RDS 是唯一业务事实库，Redis/Tair 是第一版生产必需组件。
- app、worker、migration 职责互斥。
- ECS、RDS、Tair 的网络边界采用同地域、同 VPC、最小白名单原则。
- ACR 和集中日志是生产发布与运维基线。
- 未把未核验资源写成已部署。
- 未重新定义业务、Schema 或 API。
