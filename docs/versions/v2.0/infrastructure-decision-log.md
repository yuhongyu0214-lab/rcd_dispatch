## 1. 使用规则

- 决策状态只能是 `PROPOSED / ACCEPTED / SUPERSEDED / REJECTED`。
- 被替代的决策保留原记录，通过 `SUPERSEDED` 和关联新决策说明现状，不通过删除制造“从未发生”。
- 本日志不重新定义产品、Schema、API、状态机或兼容策略。
- “ACCEPTED”表示方向已经批准，不表示相应云资源已创建或生产验收已通过。
- 资源实时状态未独立核验时必须明确写“未核验”。

### INFRA-001：阿里云作为中国大陆正式生产主线

- 决策编号：`INFRA-001`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：Railway 的网络、套餐和中国大陆生产边界不适合作为本项目长期正式基线。
- 决定：正式生产架构以阿里云为唯一主线；具体资源必须重新盘点、建设和验收。
- 不选择什么：Railway 与阿里云双生产主线；把历史 Demo 直接升级为生产。
- 影响：R4～R7 重新冻结基建档案；Gate 3 在阿里云完成重新验收前保持暂停。
- 回滚或退出条件：若阿里云不再满足合规、网络或成本要求，必须新增决策替代，不得静默切换。
- 关联文档：[基础设施架构 V2](infrastructure-v2.md)
- 批准人：用户

### INFRA-002：Railway 正式生产裁决被替代

- 决策编号：`INFRA-002`

- 背景：Gate 3 曾将 Railway 升格为正式 app/worker 平台，但部署来自未提交工作区并存在套餐和网络边界问题。
- 决定：撤销 Railway 正式生产结论；已有部署、测试和部署 ID 只作为历史 Demo 与审计证据。
- 不选择什么：删除历史证据；继续把 Railway runbook 当正式生产手册。
- 影响：Railway 专属配置不得进入阿里云生产基线；平台无关 worker/outbox 成果仍可独立终审。
- 回滚或退出条件：无自动回滚；若未来重新评估 Railway，必须新建决策并重新验收。
- 关联文档：[基础设施架构 V2](infrastructure-v2.md)
- 批准人：用户

### INFRA-003：CloudBase 仅用于隔离预览和验证

- 决策编号：`INFRA-003`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：CloudBase 可能便于临时预览，但不能形成第二套生产事实或秘密边界。
- 决定：如保留 CloudBase，只允许假数据或脱敏后的独立测试数据，不得拥有生产秘密和生产数据权限。
- 不选择什么：CloudBase 作为生产数据库、生产调度环境或正式数据副本。
- 影响：是否继续作为持续环境由 `INFRA-017` 裁决；如未来临时启用，仍必须独立账号、数据和凭据。
- 回滚或退出条件：发现生产数据、秘密或生产网络权限时立即停止并清理。
- 关联文档：[基础设施架构 V2](infrastructure-v2.md)
- 批准人：用户

### INFRA-004：RDS PostgreSQL 是唯一业务事实库

- 决策编号：`INFRA-004`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：订单、调度、执行、预警和审计必须有唯一、可事务提交的事实来源。
- 决定：正式业务事实只保存于 RDS PostgreSQL。
- 不选择什么：Redis/Tair、CloudBase、Railway 数据库或日志平台成为第二事实库。
- 影响：所有缓存和降级必须服从数据库事实；数据库恢复是最高优先级能力。
- 回滚或退出条件：更换数据库产品属于新的重大架构决策和数据迁移项目。
- 关联文档：[数据架构 V2](data-architecture-v2.md)、[基础设施架构 V2](infrastructure-v2.md)
- 批准人：用户

### INFRA-005：Redis/Tair 是 V2 第一版生产必需组件

- 决策编号：`INFRA-005`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：实时位置、在线状态、ETA 短缓存和短锁是 V2 滚动调度所需能力。
- 决定：第一版生产部署 Redis/Tair，并保持“短期实时数据，不保存业务事实”的边界。
- 不选择什么：完全移除 Redis 后仍声称 V2 实时调度完整；把 Redis 当持久业务库。
- 影响：必须建设连接、监控、故障降级和恢复后缓存重建。
- 回滚或退出条件：只有业务与数据权威另行证明替代方案后才能更换。
- 关联文档：[数据架构 V2](data-architecture-v2.md)、[运维指南 V2](operations-guide-v2.md)
- 批准人：用户

### INFRA-006：当前应用采用 ECS + Docker + Nginx

- 决策编号：`INFRA-006`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：当前 Next.js 模块化单体不需要微服务或 Kubernetes。
- 决定：ECS 承载 Docker；Nginx 提供 HTTPS 与入口转发；app/worker/migration 使用同一镜像的不同角色。
- 不选择什么：Kubernetes、第二套后端、为基础设施迁移拆微服务。
- 影响：第一版拓扑简单，但单 ECS 模式存在明确单点。
- 回滚或退出条件：容量、可用性或组织复杂度经证据证明当前模式不足后新建决策。
- 关联文档：[基础设施架构 V2](infrastructure-v2.md)
- 批准人：用户

### INFRA-007：ACR 是正式生产镜像来源

- 决策编号：`INFRA-007`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：生产部署必须把代码提交、镜像和回退版本关联起来。
- 决定：生产镜像进入 ACR，以 commit SHA 和 digest 形成不可变追溯链。
- 不选择什么：从开发机复制代码；从未提交工作区直接部署；仅用可变 `latest` 标识生产版本。
- 影响：构建、发布和回退必须记录镜像 digest。
- 回滚或退出条件：更换镜像仓库需保证等价的不可变、权限和审计能力。
- 关联文档：[部署指南 V2](deployment-guide-v2.md)
- 批准人：用户

### INFRA-008：集中日志是生产硬要求

- 决策编号：`INFRA-008`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：单机文件或临时终端日志无法支撑生产查询、告警和事故追溯。
- 决定：生产必须集中采集结构化日志；第一版产品选择由 `INFRA-018` 冻结为阿里云 SLS，但 SLS 不是业务契约。
- 不选择什么：只保留容器本地日志；把业务操作审计和运行日志混成一种记录。
- 影响：需确定保留期、脱敏、查询、告警和费用预算。
- 回滚或退出条件：若更换日志产品，必须保持结构化、集中保存、查询、告警和权限能力。
- 关联文档：[运维指南 V2](operations-guide-v2.md)
- 批准人：用户

### INFRA-009：app、worker、migration 三项职责分离

- 决策编号：`INFRA-009`
- 日期：2026-07-29
- 状态：`ACCEPTED`
- 背景：多个常驻进程自行迁移会产生并发、权限和回退风险。
- 决定：app/worker 常驻，migration 每次发布最多运行一次；三者使用同一镜像但启动命令、权限和生命周期不同。
- 不选择什么：app/worker 启动时自动并发迁移；三个角色使用不同代码版本。
- 影响：发布必须在 migration 成功后再启动新 app/worker。
- 回滚或退出条件：任何编排方式变化都必须保持一次迁移和职责隔离。
- 关联文档：[部署指南 V2](deployment-guide-v2.md)
- 批准人：用户
