# 人车单生产运维、监控与恢复指南 V2

> 文档版本：`RCD-OPS-V2.0-R6-20260810`
>
> 状态：Gate 3-R 已冻结；最终运行资源、健康、10 单、outbox 和故障/回退证据一致性审查通过，整机与 RDS 灾备仍为独立演练
>
> 权威范围：生产运行、监控、日志、备份、恢复、事故处理、安全复核和容量成本
>
> 非权威范围：部署命令、业务 DTO、状态机和未批准的高可用采购

## 1. 白话结论

系统上线后不能只看“网页能不能打开”。必须分别知道入口、app、worker、数据库、Redis/Tair、高德和日志是否正常；必须能发现 worker 停摆、事件积压、数据库变慢、证书过期和费用异常；发生故障后必须知道最多能丢多少数据、多久恢复、由谁决定升级或回退。

本文定义运维基线，不表示监控、备份或告警已经在阿里云创建。

## 2. 运行对象与责任边界

| 对象 | 必须观察 | 故障影响 |
|---|---|---|
| DNS/HTTPS/Nginx | 解析、证书、连接、4xx/5xx、转发延迟 | 用户无法进入或请求异常 |
| Next.js app/API | liveness、readiness、错误率、P95/P99、资源占用 | 页面/API 不可用或变慢 |
| worker | 最后成功时间、连续失败、耗时、处理/失败数 | outbox 积压、调度事件延迟 |
| RDS PostgreSQL | 连接、CPU、内存、存储、IOPS、锁、慢查询、备份 | 业务事实读写受阻 |
| Redis/Tair | 连接、延迟、内存、淘汰、命中率、锁错误 | 位置/缓存/短锁降级 |
| ACR | 镜像可取、digest、保留和权限 | 无法发布或回退 |
| 高德 | 成功率、延迟、超时、配额、无路径 | ETA/地图能力降级 |
| 集中日志平台 | 采集延迟、丢失、查询、告警、费用 | 无法排障和追溯 |
| ECS/Docker | 实例、磁盘、CPU、内存、容器重启 | 一个或多个运行角色中断 |

## 3. 监控与告警基线

### 3.1 app/API

至少监控：

- 请求量、成功率、4xx/5xx；
- P50、P95、P99 响应时间；
- liveness/readiness；
- 进程重启、CPU、内存、事件循环和磁盘；
- 数据库连接池与 Redis/Tair 连接；
- 登录、鉴权失败和异常来源流量趋势。

具体告警阈值需要基于预生产和试运行基线确定，不在没有流量证据时伪造“合理数字”。

### 3.2 worker 与 outbox

至少监控：

- worker 最后一次成功时间；
- 连续失败次数；
- 每轮 `processed / failed / skipped`；
- 待处理事件数量和最老事件年龄；
- 领取租约数量、超时租约和接管次数；
- 单轮耗时是否逼近或超过调度周期；
- 第一版每分钟处理周期是否持续按时执行；
- baseline 事件是否按稳定十分钟桶持续产生；
- worker 副本数是否仍为获准值。

worker 的成功必须来自实际处理证据，不能用 app 健康代替。

### 3.3 RDS

至少监控：

- 活跃/空闲/等待连接；
- 慢查询、长事务、锁等待和死锁；
- CPU、内存、存储使用率、IOPS 和剩余空间；
- 备份成功、恢复点覆盖和复制/恢复异常；
- schema migration 记录和异常 DDL；
- 业务表与 outbox 的增长趋势。

### 3.4 Redis/Tair

至少监控：

- 可达性、连接失败和重连；
- 延迟、内存、淘汰、命中率；
- 锁获取失败、锁忙与所有权错误；
- 最新位置和 ETA 缓存的过期行为；
- 异常 Key 增长和费用。

Redis/Tair 不是业务事实库，告警与恢复不得要求从缓存反向覆盖 PostgreSQL。

## 4. 日志与审计

### 4.1 运行日志

- 应用统一使用 Pino 输出结构化 JSON 到 stdout，禁止 `console.log`。
- Nginx、app、worker、Docker 和系统日志进入阿里云 SLS；该产品选择不改变结构化日志业务契约。
- 日志至少可按环境、服务、版本、时间、级别和 traceId 查询。
- 禁止记录数据库连接串、Redis 密钥、JWT、Cookie、Session、内部 worker 密钥、云密钥、证书私钥和未脱敏位置。
- Authorization 不得进入 URL；请求头和 body 默认不做完整原文记录。

2026-08-08 预生产已验证 app、worker、Nginx 的环境、服务、完整 revision、时间和字符串级别字段，以及 Docker `json-file` 单文件 `20m`、最多 `5` 个文件的轮转。2026-08-09 又完成 LoongCollector `3.2.6`、SLS 运行/安全日志、字段查询、脱敏、30/180 天留存、告警、通知和预算验收；业务操作审计仍以 PostgreSQL 为准。

### 4.2 业务操作审计

业务操作日志保存在 PostgreSQL，与系统运行日志分离。调度员修改、自动重排、状态流转、班次和预警处理的事实以业务审计记录为准，集中日志只用于运行排障。

### 4.3 保留期

| 数据 | 当前口径 |
|---|---|
| 司机历史位置 | 90 天 |
| 业务操作审计 | 1 年 |
| 运行日志 | 30 天 |
| 安全审计 | 180 天 |

自动删除必须在实施阶段验证权限、范围、审计和法律/事故保全例外后才能启用；不得仅凭文档冻结立即删除既有数据。

## 5. 依赖故障与降级边界

### 5.1 Redis/Tair 故障

- PostgreSQL 业务事实继续有效。
- 最新位置、在线状态、ETA 缓存和短锁能力可能降级。
- 已实现的数据库行锁和版本校验可作为一致性兜底候选，但必须在阿里云目标环境重新验收。
- 若无法证明自动调度仍安全，应停止自动写入或转人工处理，不得用过期位置或假 ETA 继续排程。
- 恢复后以数据库事实重建短期缓存，不从缓存反写业务事实。

### 5.2 高德故障

- 地图、地理编码或 ETA 明确标记不可用。
- 不生成演示 ETA，不用固定大数伪装真实路径。
- 依赖恢复后再按业务事件或基线规则重算。

### 5.3 RDS 故障

- 停止一切无法可靠提交的业务写入。
- 不把 Redis/Tair 提升为临时事实库。
- 按获准 RPO/RTO 选择故障恢复、时间点恢复或回退。

### 5.4 worker 故障

- app 可继续提供不依赖及时事件消费的能力，但不得把 app 健康解释为调度链路完整。
- 告警 outbox 积压和最后成功时间。
- 修复 worker 后按租约和幂等规则恢复处理，不手工删除待处理业务事件。

## 6. 备份与恢复

### 6.1 RDS

- 启用自动备份和时间点恢复能力。
- 发布迁移前额外确认新鲜恢复点。
- 定期在隔离环境执行恢复演练，不只检查“备份任务成功”。
- 恢复演练至少核对表、迁移记录、关键业务计数、outbox、权限和应用只读验证。

### 6.2 配置与镜像

- ACR 保留当前版本和获准回退版本的不可变镜像。
- Nginx、部署定义和非秘密配置进入版本控制。
- 秘密只保留在获准的秘密系统中，并有轮换/吊销记录。

### 6.3 RPO/RTO

| 指标 | 含义 | 当前状态 |
|---|---|---|
| RPO | 严重故障最多允许丢失多长时间的数据 | 设计目标不超过 5 分钟 |
| RTO | 严重故障后多久恢复核心服务 | 设计目标不超过 2 小时 |

上述数值在备份、时间点恢复和完整恢复演练通过前只称“设计目标”，不得对外承诺已经达到。

## 7. 事故等级与处理

| 等级 | 示例 | 基本动作 |
|---|---|---|
| P0 | 数据损坏/泄露、错误批量调度、生产完全不可用 | 立即停止危险写入，保护证据，通知负责人，启动恢复或回退裁决 |
| P1 | worker 长时间停止、关键依赖不可用、严重性能下降 | 限制受影响能力，告警升级，按 runbook 恢复 |
| P2 | 单一非关键功能异常、可控降级 | 记录、排期修复、持续观察 |

所有事故遵循：

```text
发现 → 限制影响 → 保护证据 → 判断数据安全
→ 恢复/回退 → 验证 → 复盘 → 更新监控和文档
```

数据安全优先于快速恢复。不得为了恢复页面而删除业务事实、关闭鉴权或开放全网白名单。

## 8. 安全与权限复核

至少按固定周期和重大变更后复核：

- ECS、RDS、Tair、ACR、SLS 账号和角色；
- 安全组、白名单、VPC 和公网暴露；
- app、worker、migration 数据库权限；
- 管理员、司机、ingest 和内部 worker 密钥；
- 证书到期和密钥轮换；
- 中国大陆正式公网域名的 ICP 备案/许可状态与主体、接入资源一致性；
- 公开注册、演示账号和默认密码；
- 离职/停用人员权限；
- 日志是否出现秘密或未脱敏位置。

发现泄露嫌疑时先吊销/轮换，再调查，不等待确认“是否真的被使用”。

### 8.1 ECS/Docker 主机运行基线

- `root` 仅用于首次引导和受控恢复；日常运维使用具名账号并保留可审计的提权记录。
- `docker` 组成员具有等同 root 的主机控制能力，必须按高权限账号管理、定期复核和及时撤销。
- Docker daemon 只监听本机 Unix socket，不开放公网管理端口；安全组不得放行 Docker API。
- Docker 与 containerd 必须设为开机启动，并在每次维护后分别核对服务状态、版本和容器重启原因。
- ECS 仅保存 ACR 只读拉取凭证；推送凭证、数据库 DDL 凭证和应用运行凭证不得混用。
- Docker `json-file` 日志必须配置轮转，或由 SLS 接管并验证采集；在 40 GiB 系统盘上未完成日志上限前不得启动长期运行容器。
- 每日检查磁盘、inode、容器重启次数和异常日志增长；达到告警阈值时停止继续部署，先保护日志与运行证据。
- SSH 来源限制、私钥轮换、离职账号撤销和恢复通道必须进入固定复核；关闭 root 登录前先验证具名账号可恢复主机。

### 8.2 一次性 bootstrap 凭据与失败现场

- owner 密码只在获准的一次性窗口内启用；连接文件必须为 `root:root 600`，不得输出内容、写入历史证据或注入常驻 app/worker。
- 执行完成后必须轮换 owner 密码、验证旧凭据被拒绝、删除临时文件，并记录 app/worker/Nginx 运行状态未发生意外变化。
- “写入成功、后置核验失败”属于需要保护的现场，不等于可以重跑。先用 app 长期身份只读盘点计数和内容，再决定是否需要单独批准的最小修正。
- 兼容触发器造成派生字段偏差时，只修正已经明确授权的标记记录和字段；禁止同时清理、补写订单、修改权限或执行 migration。
- 当前 G3E2E R2.2 已完成 `3/6/5/8` 基础资料核验、`5` 名司机 `onShift` 最小修正和 owner 关闭。详见 [G3E2E R2.2 隔离基础资料写入与核验](../../status/2026-08-09-gate3r-g3e2e-base-data-bootstrap.md)。

## 9. 容量、费用和异常支出

- 观察 ECS CPU/内存/磁盘、RDS 连接/存储/IOPS、Tair 内存、日志写入/存储、ACR 镜像和高德调用量。
- 设置月度预算和异常增长告警。
- 日志、位置历史和镜像保留策略必须同时考虑合规、恢复和费用。
- 单 ECS 试运行的容量上限必须通过压测和真实流量观察确定。
- 扩容前先定位瓶颈，禁止在没有证据时直接引入微服务或 Kubernetes。

## 10. 单 ECS 试运行风险

第一版已选择单 ECS：

- ECS 故障会同时影响 Nginx、app 和 worker；
- 发布可能需要维护窗口；
- 容器重启不等于主机级故障切换；
- 必须确保 RDS、Tair、镜像和日志不只存在于该主机；
- 必须有实例重建、镜像回退、配置恢复和数据库连接验证手册。

该模式只能作为明确接受单点的成本优先阶段，不能宣传为高可用。

### 每周

- 失败事件和重试趋势；
- 权限/公网暴露异常；
- 备份覆盖状态。

### 定期演练

- RDS 隔离恢复；
- 上一镜像回退；
- Redis/Tair 不可用降级；
- worker 停止与积压恢复；

## 12. 2026-08-10 故障与恢复实施证据

- worker 停止期间 app HTTPS 保持 `200`；正常 10 分钟基线事件在隔离短锁下形成
  `pending=1 / failed=1 / DISPATCH_RESOURCE_BUSY` 积压。
- 释放锁并启动单副本 worker 后，事件第二次尝试成功，`lastError=null`、全局
  `pending=0 / failed=0`，服务恢复耗时 14 秒。
- 应用回退 `084649f4…` 用时 30 秒，恢复 `958afca…` 用时 31 秒；两阶段真实依赖 readiness、
  HTTPS、运行身份、单 worker、outbox 和冻结 10 单执行状态通过。
- 上述时间满足当前服务级演练的 `RTO ≤ 2 小时` 设计目标，但不替代 RDS 隔离恢复、整机重建，
  也不能单独证明灾难恢复 RPO。
- 证据和失败现场见[故障注入与应用回退验收](../../status/2026-08-10-gate3r-fault-rollback-acceptance.md)。

## 13. R7 冻结与实施前置

- `RPO ≤ 5 分钟`、`RTO ≤ 2 小时` 是第一版设计目标，必须通过演练验证；
- 位置、业务审计、运行日志和安全日志分别保存 90 天、1 年、30 天和 180 天；
- 第一版采用单 ECS 和 SLS；
- P0/P1 责任人、升级通知、SLS 预算阈值、演练频率、运维窗口和对外通知规则延后到资源盘点与实施步骤确定；
- 实施型事项未确定前不得部署生产。
