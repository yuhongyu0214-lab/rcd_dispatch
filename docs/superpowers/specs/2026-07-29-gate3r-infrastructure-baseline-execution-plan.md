## 4. 全程硬性约束

### 4.1 当前工作现场只读

在安全快照通过恢复验证前，禁止：

- `git reset`、`git checkout --`、`git restore`、`git clean`；
- stash 当前工作、删除或移动现有文件；
- 自动格式化整个仓库；
- 安装、升级或删除依赖；
- 运行会修改数据库的 Prisma 命令；
- 连接生产库执行写操作；
- 修改 Railway 或阿里云资源；
- 提交、合并、变基、推送当前 Gate 3 分支；
- 为第二轮 Web、司机端或观测功能创建分支。

### 4.2 不复制秘密

保护现场时只记录环境变量名称和是否配置，不记录值。以下内容不得进入快照文档、补丁、压缩包、日志或提交：

- `.env.local` 和其他真实环境文件；
- 数据库、Redis、CloudBase、Railway、阿里云密钥；
- JWT、Cookie、Session、Ingest、worker 内部密钥；
- SSH 私钥、证书私钥、访问令牌；
- 未脱敏的司机位置和真实订单数据。

### 4.3 文档不重新定义业务

四份基建档案不得重新定义：

- PRD 产品范围、A/B/C 规则或状态机；
- Prisma 业务模型和迁移语义；
- API 路径、DTO、错误码和鉴权角色；
- V1/V2 兼容策略；
- 车辆是否参与调度；
- 多租户、计费、复杂组织权限等未进入当前 PRD 的功能。

出现跨领域冲突时，停止该条编写，记录到决策日志并交用户裁决。

## 10. R4：四份基建权威档案

### 10.1 `infrastructure-v2.md`

**权威范围：生产基础设施架构与平台边界。**

必须定义：

- 阿里云是中国大陆正式生产主线；
- 当前应用采用 Next.js `15.5.21` + React / React DOM `19.2.8` 的模块化单体；
- ECS + Docker + Nginx 承载当前完整应用；
- RDS PostgreSQL 是唯一业务事实库；
- Redis/Tair 是 V2 第一版生产必需组件；
- app、worker、一次性 migration 的职责边界；
- ECS、RDS、Tair 同地域、同 VPC、最小白名单；
- ACR 是生产镜像来源；
- 集中日志能力是生产硬要求，阿里云默认实现可为 SLS；
- OSS 只在文件业务出现时启用，不改变当前 PRD；
- CloudBase 仅使用假数据或脱敏后的独立测试数据；
- Railway 只保留历史 Demo 证据；
- 单 ECS 试运行与多实例高可用的边界；
- 不建设微服务、Kubernetes、分布式数据库；
- 高德只提供真实地理和 ETA 输入，不决定业务调度；
- 平台适配不得污染调度核心。

## 13. 需要用户批准的业务化选择

文档可以给出推荐值，但不得替用户静默决定：

1. 阿里云生产地域：原则上跟随现有 RDS 地域；
2. 第一版可用性：
   - 成本优先试运行：单 ECS，接受明确单点和维护窗口；
   - 稳定生产：多实例 + 负载均衡，成本更高；
3. RPO：最多允许丢失多少时间的数据；
4. RTO：严重故障后多久恢复；
5. 司机位置、操作日志、运行日志各保存多久；
6. CloudBase 是否保留；若保留，只允许假数据或脱敏独立测试数据；
7. 是否第一版启用 OSS；仅在已有文件业务时启用；
8. 集中日志默认使用 SLS，是否存在合规或预算限制。

上述选择必须附大白话影响说明和费用影响，不要求用户理解云产品术语后才能决策。
