# 双端账号变更交付说明

这是本次功能的实施说明，不是已部署或已验收结论。代码基线为
`b2887d3718f34bf3cc068d07b505d33065e77c7c`；本说明随双端账号代码提交保存。
最新代码 SHA、镜像与部署进度分别以仓库状态总览和受控发布证据为准，不能由本说明推定已上线。
用户 2026-09-13 明确要求注册账号同时拥有 Web 调度和司机 H5 权限。
这取代原来按 admin/dispatcher/driver 分端访问的产品规则；不改变司机任务归属规则。

## 行为

- 现有 admin、dispatcher、driver 用户均可使用 Web 调度（含派单、改派等）和 H5 入口。
  不批量修改历史 role、密码或会话；system/ingest/未知角色不获得交互权限。
- 新注册账号固定 dispatcher，必须填写手机号、姓名、密码和所属门店；
  User 与 Driver 在同一个 Serializable 事务内创建/关联。
  新 Driver 为 OFFLINE/onShift=false，不自动上线派单。
- 同手机号已有活跃且未绑定的 Driver 可复用；已绑定其他账号、停用或门店冲突时拒绝自动处理。
  不抢占别人的档案、不复活停用司机、不修改已有门店或工作状态。
- 旧账号缺 driverId 时可进入 H5 的档案完善页，确认原档案或选择门店后提交
  `POST /api/v2/account/driver-profile`。该接口只接受可选 storeId，
  身份取自会话，手机号/姓名取自数据库，结果为统一 V2 响应中的 driverId。
- 已有绑定的账号不重新写库。重复/并发请求依靠唯一键与串行化事务防止重复关联；
  冲突返回 409，失败没有半份档案。真实 PostgreSQL 并发与回滚仍需部署前集成验证。
- 只有 Driver 记录、没有 User 的手机号仍不能登录：那不是已注册账号。
- 预生产/生产的公开注册仍然关闭。受控开户也应遵循上述双端及门店要求，
  不向公开互联网开放注册，不把 DBA 凭据放进 app 容器。

## 部署前置（尚未执行）

1. 复核新代码 diff、测试、镜像扫描；保存新代码 SHA、digest，与旧候选区分。
2. 由受控 DBA 使用 psql 连接 `rcd_v2_preprod`，执行本目录
   `prepare-preprod-acl.sql`；连接凭据通过受控机制提供，不写命令、日志或源码。
   完整保存**首次成功执行**的输出，尤其是三项新增权限标志和 rollback_sql。
3. 脚本只补缺少的 Driver INSERT、User UPDATE(driverId)、User UPDATE(updatedAt)。
   这支持旧账号自助补齐司机档案；不会赋予应用 User INSERT、密码/role UPDATE、
   DELETE、DDL、迁移权限或把任何权限授予 worker。预生产开户仍走受控管理身份。
4. 用应用数据库身份，在隔离的预生产测试数据上验证新增档案/关联与事务回滚。
   确认无法改密码/角色、无法删除；若部署时已有额外权限，应单独记录，不能把它们误算成本次新增。
5. 此次没有 Schema 或 migration 变化。沿用分阶段部署和健康检查流程，不能在运行容器里临时提权。

## 真机验收

用各历史角色分别验证 Web、H5 两个直接入口和登录后的 next 跳转；
缺档案用户先确认门店再进入任务列表。Safari/微信与鸿蒙须使用同一账号对照，
不能以两台设备登录不同身份的结果判断浏览器兼容性。
H5 验证只读取/执行本人任务；Web 按新规则验证调度操作。
停用司机、手机号冲突、门店停用必须有明确提示，不得静默返回首页。

## 回退

先回退应用镜像/发布配置并核验健康，再由 DBA 在**同一预生产库**执行首次授权输出的
rollback_sql（建议置于 BEGIN/COMMIT 中）；只撤销此次新增的权限。
不要手工照抄全量 REVOKE，也不要用重复执行输出覆盖首次权限基线。
账号与档案业务数据保留，不自动删除、改密码、解绑或批量重置。
